Writing and compiling ATLAS

ATLAS reads a compact DSL and emits IEC 61131-3 Structured Text, Ladder-style textual output, or PLCopen XML, targeted at Siemens, CODESYS, or Rockwell. This guide walks through the language rung by rung, then the CLI flags that take a rule from source to a certified, audited artifact.

01

Install & build

ATLAS is a C99 project, MIT-licensed and hosted on GitHub. Clone it, build a debug binary, and compile the bundled sample program to confirm your toolchain works.

Get the source
git clone https://github.com/Thehackerz-creator/Atlas-compilers.git
cd Atlas-compilers
Linux / macOS
make debug
./plc_compiler_debug examples/program.dsl output.st
make formal_test
Windows — MSVC via CMake
cmake -S . -B build\vs2022 -G "Visual Studio 17 2022" -A x64
cmake --build build\vs2022 --config Debug
ctest --test-dir build\vs2022 -C Debug --output-on-failure
💡Full source, issues, and releases live at github.com/Thehackerz-creator/Atlas-compilers.

The general CLI shape you'll use throughout this guide:

./plc_compiler_debug <input.dsl> <output> [flags]
02

Your first rule

Every rule follows the same shape: a condition, a THEN action, and an ELSE action. Save this as first.dsl:

first.dsl
IF sensor = ON THEN motor = ON ELSE motor = OFF END

Compile it against the default target (Siemens TIA Portal) and format (Structured Text):

./plc_compiler_debug first.dsl first.st
💡Operators available in conditions: = != >= <= > <. Values are ON, OFF, or numeric literals like 100 and 3.14.
03

Timers

Add FOR <n> <unit> to a condition to require it to hold before the action fires. Timer units are SECONDS, MINUTES, and MILLISECONDS.

Timer-guarded condition
IF switch = ON FOR 5 SECONDS THEN motor = ON ELSE motor = OFF END

This compiles to a generated ST timer instance that gates the branch — you write the rule once, and ATLAS handles the timer instantiation.

04

Compound conditions

Combine conditions with AND, OR, and negate with NOT.

Compound condition
IF temp >= 50 AND switch = ON THEN fan = ON ELSE fan = OFF END
Negation
IF NOT emergency_stop = ON THEN pump = ON ELSE pump = OFF END
05

Variables & units

Declare inputs inside a VAR_INPUT … END_VAR block. Units are optional but recommended — they're preserved into the generated ST and used by semantic analysis.

Units on variables
VAR_INPUT
  temp IN celsius
  pressure : REAL IN bar
END_VAR
06

Constants

Name a threshold once and reuse it across rules. CONST declarations can carry a unit too.

MAX_TEMP = 95
CONST MIN_PRESSURE = 2 IN bar
07

Loops

WHILE … DO … END repeats its body while the condition holds — useful for supervisory logic that should keep checking a running system state.

WHILE system_active = ON DO
  IF temp >= 95 THEN cooling = ON END
END
08

Multi-state logic

For more than two states, use CASE … OF … DEFAULT … END_CASE instead of chaining IF blocks.

CASE mode OF
  1: motor = ON; fan = OFF
  2: motor = ON; fan = ON
  DEFAULT: motor = OFF; fan = OFF
END_CASE
09

Comments

Regular comments use #, //, or /* … */ and are stripped at compile time. Documentation comments — ///, ##, or /** … */ — are preserved into the generated ST as record-keeping for reviewers.

/// Boiler startup interlock
10

Multilingual DSL

Core logic keywords have aliases in Spanish, Hindi, and Arabic, so teams can write rules in the language they think in. Variable names stay PLC-safe identifiers regardless — generated ST sanitizes names for the target platform.

Spanish alias — identical to the English form
SI temp >= MAX_TEMP ENTONCES alarm = ON SINO alarm = OFF FIN
11

Recipes

The IDE can hook in reusable logic templates with USE, so a common sequence — like a boiler startup — doesn't need to be re-written per project.

USE boiler_startup_sequence
12

Vendor targets & output formats

Pick a vendor with --target and an output shape with --format. The DSL source doesn't change — only the emitted artifact.

--target siemensSiemens TIA Portal S7-1200/1500 (default)
--target codesysCODESYS V3
--target rockwellRockwell Studio 5000
--format stStructured Text (default)
--format ladderLadder-style textual output
--format plcopenPLCopen XML
./plc_compiler_debug first.dsl first.st --target codesys --format st
13

Safety analysis

Run the IEC 61508 safety engine with --safety. It checks for rule conflicts, missing safe-state paths, and emergency-stop coverage, and can gate the build outright.

--safetyRun IEC 61508 safety analysis
--safety-report <path>Write the safety report to a file
--min-sil <1-4>Fail unless safety analysis reaches the requested SIL level
--require-estopFail unless an emergency-stop rule is present
--require-elseFail if output rules omit ELSE / default safe-state paths
--fail-on-safetyFail on safety-critical findings
⚠--require-else is worth turning on early: every branch you write should define what happens in the safe state, not just the energized one.
14

Diagnostics

Maintainability and lint-style checks run with --diagnostics, in a format suited to a person or a CI pipeline.

--diagnosticsRun maintainability and code-quality diagnostics
--diagnostics-report <path>Write diagnostics report to a file
--diagnostics-formattext / json / markdown / html
--fail-on-warningsFail on compiler or diagnostics warnings
15

Industrial hardening

--industrial applies paranoid hardening plus safety, diagnostics, deterministic output, and no-overwrite gates in a single flag — a 30-control evidence pack covering integrity hashing, sandboxing, atomic writes, and safety gates.

./plc_compiler_debug plant.dsl plant.st --industrial --min-sil 2 --safety-report evidence.json

See the hardening pack breakdown on the homepage for the full control list.

16

Deployment CPU profiles

ATLAS stays a PLC DSL compiler — it doesn't replace GCC — but --cpu attaches deployment metadata used for security manifests, reproducible builds, and review evidence.

--cpu <arch>x86_64, x86, armv7, aarch64, riscv32, riscv64, ppc64, mips32, mips64, sparc64, wasm32
--list-cpusPrint supported CPU profiles
17

Vendor translation

Already have Structured Text from one vendor? Translate it to another without round-tripping through the DSL.

--translate-from <vendor>Translate existing vendor ST from Siemens, CODESYS, or Rockwell
--translate-to <vendor>Translate existing vendor ST to Siemens, CODESYS, or Rockwell
