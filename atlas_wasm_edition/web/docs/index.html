Overview & Core Architecture

ATLAS is a high-integrity domain-specific language (DSL) compiler designed to compile, verify, and validate PLC logic. Unlike traditional PLC development models where safety checks are executed manually after coding, ATLAS incorporates the IEC 61508 safety compliance checkpoints directly into the compilation pipeline itself.

By compiling safety checks into the parser and static analysis phase, ATLAS halts builds containing structural logic failures, conflict writes, or unguarded critical loops before binary generation occurs. It outputs clean, vendor-conforming Structured Text (ST) conforming to IEC 61131-3, compatible with Siemens TIA Portal, CODESYS, and Rockwell Studio 5000.

Language Reference

The ATLAS language has a deterministic, clean syntax that reduces scanning jitter and prevents human nesting errors. The layout is divided into variable declarations and logical statements.

Keywords & Statement Blocks

Keyword Syntax / Structure Description
VAR / END_VAR VAR ... END_VAR Declares internal variables not exposed to physical addressing.
VAR_INPUT VAR_INPUT ... END_VAR Declares physical inputs (e.g. pressure switches, pushbuttons).
VAR_OUTPUT VAR_OUTPUT ... END_VAR Declares physical outputs (e.g. coils, solenoids, alarm sirens).
IF / THEN / ELSE IF [cond] THEN [act] ELSE [act] END Standard conditional logic. Requires explicit safe-state fallbacks.
FOR [n] [UNIT] IF [cond] = ON FOR 3 SECONDS THEN ... Timer guard that executes actions only when the condition is stable.
CASE / OF CASE [var] OF 1: ... DEFAULT: ... END_CASE Multi-branch selection block. Ideal for step sequence transitions.
WHILE / DO WHILE [cond] DO [act] END Resource-bounded loops. Max loop count checked statically.

Data Types

  • BOOL — Binary status (values: ON / OFF or TRUE / FALSE).
  • INT — 16-bit signed integer (range -32,768 to 32,767).
  • REAL — 32-bit single-precision floating point for continuous process variables.
  • TIMER — IEC 61131-3 compliant TON on-delay timer instances generated during output.

Safety Annotations

Annotations inject metadata into control variables. They are placed inline during declarations:

  • @CRITICAL — Designates a variable whose failure could lead to hazardous operations. Enforces safety-critical checking routines on assignments.
  • @ESTOP — Marks a physical input button as the Emergency Stop circuit.
  • @SIL1 - @SIL4 — Declares the Safety Integrity Level target of the block (conforming to IEC 61508 standard).
# Declaring variables with annotations
VAR_INPUT
  e_stop_button  : BOOL @ESTOP
  limit_switch_1 : BOOL
END_VAR

VAR_OUTPUT
  pump_motor     : BOOL @CRITICAL @SIL3
  safety_light   : BOOL
END_VAR

Address & I/O Mapping

Industrial PLC compilers require physical addressing (e.g. %I* or %Q* blocks) to bind software variables to hardware cards. ATLAS automates address mapping by scanning I/O registers during compilation:

  • Inputs (VAR_INPUT) are automatically mapped to read-only register blocks starting at offset %IX0.0.
  • Outputs (VAR_OUTPUT) are mapped to writeable register offsets starting at %QX0.0.
  • Critical outputs (@CRITICAL) are assigned offset addresses in reserved, hardware-hardened registers to allow the safety PLC controller to force them low on watchdog failures.

Safety Framework (11-Point Checkpoint)

Every compilation runs the safety engine, assessing logic against these 11 rules. Violations trigger compile warnings or hard errors.

1. Conflicting Outputs

Detects if separate rules try to write contradictory values (ON and OFF) to the same variable during the same program cycle.

2. Missing ELSE Fallback

Ensures that conditional controls assign a default, deterministic safe state (usually OFF) if the IF condition is false.

3. Emergency Stop Coverage

Validates that any output variable flagged as @CRITICAL is explicitly forced to OFF in the event that an @ESTOP input is triggered.

4. Circular Dependency Analyzer

Scans the AST dependency tree for logic loops (e.g. A depends on B, which depends on A) that could cause execution jitter or infinite scanning loops.

5. Guard Timer Safety

Ensures time delays used on critical interlocks do not exceed maximum safety-reaction times specified in the SIL parameters.

6. Scan Write-Write Limits

Flags variables written to by more than 2 execution paths. Multiple writes cause order-of-scan bugs that lead to volatile field behaviors.

7. Deadlock Output Coverage

Verifies that every declared output has at least one code path capable of asserting it ON and one path asserting it OFF.

8. State Determinism

Validates that state machine transitions do not have overlapping conditional guards, guaranteeing only one state can active at a time.

9. Static Contradiction Analysis

Performs boolean satisfiability checks to ensure impossible statements (like X = ON AND X = OFF) cannot block logic cycles.

10. Stack & Resource Limits

Enforces maximum AST depth limits to prevent stack overflow on low-power PLC processor units.

11. SIL Scoring Metric

Aggregates cyclomatic complexity, safety coverage, and diagnostics to calculate a composite Safety Integrity Level score (0 - 100).

Browser WASM API Reference

ATLAS is fully compiled into WebAssembly (WASM). You can load the compiler module inside any modern web application to parse DSL in client-side scripts.

// 1. Initialize the WebAssembly module
const moduleInstance = await AtlasCompilerModule();

// 2. Wrap the C compiler bridge functions
const compileDSL = moduleInstance.cwrap("atlas_compile_demo", "number", ["string"]);
const releaseMemory = moduleInstance.cwrap("atlas_free", null, ["number"]);

// 3. Compile source code
const sourceCode = `
VAR_OUTPUT
  heater : BOOL @CRITICAL
END_VAR
IF temp_high = ON THEN heater = OFF ELSE heater = ON END
`;

const resultPointer = compileDSL(sourceCode);
const resultJSON = moduleInstance.UTF8ToString(resultPointer);

// Always release C-memory pointer after parsing!
releaseMemory(resultPointer);

const compileOutput = JSON.parse(resultJSON);
console.log("Structured Text Output:", compileOutput.st);
console.log("Safety Findings:", compileOutput.safety);

Compiler Source & Directories

Key source code folders in the ATLAS repository for core compiler development:

  • src/core/lexer.c — Tokenizes DSL inputs, filters whitespace, and extracts metadata comments.
  • src/core/parser.c — Generates the AST using recursive descent. Enforces limits on statement density.
  • src/core/semantic.c — Resolves symbol addresses, types, and variables declaration blocks.
  • src/safety/ — Static analysis checks executing the 11 safety checkpoints.
  • src/security/ — Calculates checksums, builds hashes, and appends SHA-256 signatures to build logs.
  • wasm/atlas_wasm_bridge.c — Exposes string-handling APIs to JavaScript environments via Emscripten.
